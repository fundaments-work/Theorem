# Distribution

How Theorem is packaged and distributed across platforms.

---

## GitHub Releases (all platforms)

Every tagged release on GitHub produces:
- **Linux**: `.deb`, `.AppImage`, `.rpm`
- **macOS**: `.dmg`
- **Windows`: `.msi`, `.exe` (NSIS)
- **Android**: `.apk` (multiple ABIs)

Users download these directly from
<https://github.com/fundaments-work/Theorem/releases/latest>.

---

## In-App Updater (desktop)

The app itself can check for updates via
**Settings → About → Check for Updates**. This downloads the new version
from GitHub Releases and installs it. Works on Linux, macOS, and Windows.

---

## Linux Package Managers

### AUR (Arch Linux — paru / yay)

There is no official AUR package yet. A [PKGBUILD](./PKGBUILD) is included in
this repository under `docs/PKGBUILD`.

To install directly from the local PKGBUILD:
```bash
cd docs
makepkg -si
```

To submit to AUR: <https://wiki.archlinux.org/title/AUR_submission_guidelines>

Steps to publish:
1. Fork the `aur` repository on Arch Linux
2. Copy `docs/PKGBUILD` to a local checkout
3. Replace `sha256sums` with actual hashes (run `makepkg -g` in the directory)
4. Run `makepkg --printsrcinfo > .SRCINFO`
5. Commit and push to the AUR

### APT (Debian / Ubuntu — apt)

Users can install the `.deb` directly from GitHub Releases:
```bash
curl -LO https://github.com/fundaments-work/Theorem/releases/latest/download/Theorem_1.0.8_amd64.deb
sudo dpkg -i Theorem_1.0.8_amd64.deb
```

For an auto-updating apt repository, you have several options:

1. **OpenSUSE Build Service (OBS)** — Builds and hosts debs for multiple
   distributions: <https://build.opensuse.org/>
2. **GitHub Pages repo** — Host a simple apt repository on GitHub Pages:
   - Create a `repo` branch
   - Add debs + `Packages.gz` metadata
   - Users add `deb https://fundaments-work.github.io/Theorem/apt ./`
3. **Cloudsmith / Packagecloud** — Paid hosted repos.

### RPM (Fedora — dnf)

The CI already builds `.rpm` files. Install directly:
```bash
sudo dnf install https://github.com/fundaments-work/Theorem/releases/latest/download/Theorem-1.0.8-1.x86_64.rpm
```

For a COPR repository: <https://copr.fedorainfracloud.org/>

### AppImage (universal)

The AppImage from GitHub Releases runs on any Linux distribution without
installation:
```bash
chmod +x Theorem-1.0.8-x86_64.AppImage
./Theorem-1.0.8-x86_64.AppImage
```

For AppImageHub integration (discoverable by tools like `appimagelauncher`):
1. Create a `.github/workflows/appimage.yml` that runs `appimaged`
2. Or submit on <https://www.appimagehub.com/>

## What the CI Does Now

The current CI (`.github/workflows/release.yml`) builds all artifacts on tag
push. For Linux specifically:

| Format | Job | Artifact |
|--------|-----|----------|
| `.deb` | `build-linux` | `Theorem_{version}_amd64.deb` |
| `.AppImage` | `build-linux` | `Theorem_{version}_amd64.AppImage` |
| `.rpm` | `build-linux` | `Theorem-{version}-1.x86_64.rpm` |
| `latest.json` (updater) | `build-linux` | Auto-generated by `tauri-action` |

To trigger a build:
```bash
git tag v1.0.8
git push origin v1.0.8
```

After the workflow completes, all artifacts appear on the GitHub Releases page
at <https://github.com/fundaments-work/Theorem/releases>.
